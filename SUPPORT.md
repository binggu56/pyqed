# Getting support

Use the [documentation](https://docs.pyqed.org/) first, especially the
installation, quickstart, capability-status, and examples pages.

## Questions and reproducible problems

Open an issue at <https://github.com/binggu56/pyqed/issues> and include:

- the PyQED release or Git commit (`git rev-parse HEAD`);
- whether the source tree has local changes (`git status --short`);
- Python, operating system, architecture, and relevant dependency versions;
- the smallest runnable input that shows the problem;
- complete error text as text, not only a screenshot;
- units, basis/grid/model parameters, tolerances, and optional backend; and
- expected behavior and the reference used for that expectation.

Remove credentials, private data, and proprietary inputs before posting. For a
security issue, follow `SECURITY.md` instead of filing publicly.

## Scope

Community support is best effort. Maintainers cannot guarantee response times,
debug unpublished local modifications, or validate every physical model. A
minimal reproducer and a focused test substantially improve the chance of a
useful answer.
